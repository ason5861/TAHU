# TAHU v0.2 中文说明

TAHU 的目标是：AI 提出操作，由独立于模型的服务检查授权，再决定是否执行。本版把“读取资料、派生文稿、投递结果”做成可运行的 HTTP 接口，并用 SQLite 持久保存状态。

## 已完成

- 管理员与任务使用不同凭证；任务不能创建任务、批准自己或读取管理日志。
- 每个任务有独立资料范围、流向规则、操作预算、尝试上限及有效期。
- 读取受限资料后，限制随任务持续保留，隐瞒来源也不能清除。
- 一次性批准绑定任务、资料、内容和目的地，并在短时间后失效。
- 停止状态在服务重启后仍然有效。
- 并发审批消费、投递、日志和额度扣除处于同一个数据库事务。
- 重试相同请求不会重复投递；修改请求后复用编号会被拒绝。
- 日志不保存请求正文或凭证，提供哈希链检查。数据库本身仍含资料正文，必须保护。
- 两个 v0.1 问题已修复：异常操作类型导致崩溃，以及修改输入对象会改变历史日志。

## 运行

在仓库根目录运行，Python 3.10 或以上，无运行时第三方依赖：

```sh
python -m examples.demo
python -m unittest discover -s tests -v
python scripts/evaluate.py
```

示例会启动独立服务进程，使用真实 HTTP 请求和合成数据；它不会调用付费模型或向外部发送消息。

长期保留本地实验状态：

```sh
python -m tahu init
python -m tahu serve
```

`.tahu/operator.json` 是管理员凭证，不能交给 AI；整个 `.tahu` 目录不能公开。Windows 下需要另行设置专用服务账号与目录 ACL。本地同一用户的另一个进程通常有能力读取此文件，因此同一用户进程之间不构成可靠安全边界。

## 当前能证明什么

本次本地运行通过 39 项自动化回归测试，并完成独立服务进程演示。结果在 `reports/latest.json`。它证明指定规则在这些测试中按预期执行；测试不是独立研究，也没有真实模型的多轮攻击评估。

## 尚未完成

真实模型接入评估、邮件和外部系统执行器、操作系统沙箱、独立攻击测试、完整模型上下文隔离、真实人工审批界面、语义风险判断和全面 AI 治理。本版停止的是本服务内的后续动作，不能终止任意外部 AI 进程，也不能撤回已经送出的信息。

“人类监督”体现为管理员凭证保护的批准接口，不能证明请求背后真有人审核。“不确定性识别”仍然主要是 unknown 来源标签，不是理解一切未知风险。

不同任务的服务端状态相互隔离，但调用方必须真正隔离模型上下文，不能把读过秘密的模型换一个干净 token 后当作安全。

本版的实际投递目的地是本地 SQLite outbox，public/internal 是策略标签，不是互联网地址。不能据此宣称已解决整体 AI 失控，也没有原创性或独立安全认证结论。
