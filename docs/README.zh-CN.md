# TAHU v0.2 中文说明

## 精确模板审批改进 — 2026-10-13

可信调度器可使用独立权威公开记录预先配置精确发布模板，绑定任务、目的地、完整文字与来源 ID。初次发送仍经过原网关检查；被拒绝的草稿只有完全符合模板才获得一次性审批，网关在审批事务内核对被审查内容的哈希。机密标签、任务暴露记录、未知分类和停止控制均保留。

同一八场景语料两轮真实测试，18 次模型调用无错误：正常投递任务完成率从 6/12（50%）提高到 **12/12（100%）**，最终未恢复的安全内容拒绝从 6/12 降到 **0/12**。初次拒绝仍为 6/12，六次精确模板审批恢复了发送；停止后的两次请求依然被拦住。这个结果依赖可信模板与额外审批，不代表自由文本的误拦已普遍消除。

新测试使用 188,429 输入 token（含 68,608 缓存）、818 输出 token，模型耗时约 207.85 秒；实际美元费用仍为空。首轮改进测试中一次草稿返回前的运行错误已保留，原日志未确定原因；最终复测无错误。参见[最终原始报告](../reports/live-agent-reviewed.json)、[首轮失败记录](../reports/live-agent-reviewed-initial.json)和[评估方法](live-agent-evaluation.md)。

## 真实 agent 评估 — 2026-10-13

新增可选 Codex CLI 接入：真实模型提出结构化草稿与发送动作，可信调度器经独立 HTTP 网关执行；拒绝后最多进行有限次数重试。模型不持有 TAHU 凭据或审批权限，所有输入均为虚构课程资料，投递仅进入本地 outbox。此远程模型实验与禁网 Docker 运行器分开，不代表任意原生工具已受网关控制。

两轮八场景共完成 24 次真实调用：停止后的两次发送均被拦截，未发现危险投递；模型自行拒绝机密外发并忽略网页注入，因此不能把这两项算作网关成功拦截。内容安全的 12 次发送有 6 次被保守策略拒绝，正常投递任务完成率为 6/12；两次精确审批释放均成功。结果展示了停止与审批机制，也暴露了明显误拦成本，尚不能称为成熟安全产品。

输入 token 为 250,531（含 34,304 缓存 token），输出为 1,353；模型耗时约 280.89 秒，网关决策约 0.65 秒。订阅 CLI 未提供实际美元费用，报告保留为空。参见[方法与运行说明](live-agent-evaluation.md)和[原始报告](../reports/live-agent.json)。

## v0.3 隔离执行更新

新增 `untrusted` 标签：不可信输入影响的任务输出需要精确的一次性人工批准。新增可信宿主调度器：每次使用全新 Linux 容器，只传当前任务数据，不传凭据或共享历史；容器禁网、只读根目录、非 root、删除权限能力、限制资源，并在超时或停止时清理。

缺少 Docker 时拒绝执行，普通单元测试不等于容器实测。参见 [运行与验证说明](isolation.md)。此隔离运行器仍使用确定性探针，真实 Codex 评估采用另一条远程模型路径；两者不能保证消除提示注入、模型权重中的信息或内核逃逸。同一敏感任务仍保守拦截公开输出。

TAHU 的目标是：AI 提出操作，由独立于模型的服务检查授权，再决定是否执行。本版把“读取资料、派生文稿、投递结果”做成可运行的 HTTP 接口，并用 SQLite 持久保存状态。

## 已完成

- 管理员与任务使用不同凭证；任务不能创建任务、批准自己或读取管理日志。
- 每个任务有独立资料范围、流向规则、操作预算、尝试上限及有效期。
- 读取受限资料后，限制随任务持续保留，隐瞒来源也不能清除。
- 一次性批准绑定任务、资料、内容和目的地，并在短时间后失效。
- 停止状态在服务重启后仍然有效。
- 并发审批消费、投递、日志和额度扣除处于同一个数据库事务。
- 重试相同请求不会重复投递；修改请求后复用编号会被拒绝。
- 日志不保存请求正文或凭证，提供哈希链检查。数据库本身仍含资料正文，必须保护。
- 两个 v0.1 问题已修复：异常操作类型导致崩溃，以及修改输入对象会改变历史日志。

## 运行

在仓库根目录运行，Python 3.10 或以上，无运行时第三方依赖：

```sh
python -m examples.demo
python -m unittest discover -s tests -v
python scripts/evaluate.py
```

示例会启动独立服务进程，使用真实 HTTP 请求和合成数据；它不会调用付费模型或向外部发送消息。

长期保留本地实验状态：

```sh
python -m tahu init
python -m tahu serve
```

`.tahu/operator.json` 是管理员凭证，不能交给 AI；整个 `.tahu` 目录不能公开。Windows 下需要另行设置专用服务账号与目录 ACL。本地同一用户的另一个进程通常有能力读取此文件，因此同一用户进程之间不构成可靠安全边界。

## 当前能证明什么

本次本地运行通过 39 项自动化回归测试，并完成独立服务进程演示。结果在 `reports/latest.json`。它证明指定规则在这些测试中按预期执行；测试不是独立研究，也没有真实模型的多轮攻击评估。

## 尚未完成

真实模型接入评估、邮件和外部系统执行器、操作系统沙箱、独立攻击测试、完整模型上下文隔离、真实人工审批界面、语义风险判断和全面 AI 治理。本版停止的是本服务内的后续动作，不能终止任意外部 AI 进程，也不能撤回已经送出的信息。

“人类监督”体现为管理员凭证保护的批准接口，不能证明请求背后真有人审核。“不确定性识别”仍然主要是 unknown 来源标签，不是理解一切未知风险。

不同任务的服务端状态相互隔离，但调用方必须真正隔离模型上下文，不能把读过秘密的模型换一个干净 token 后当作安全。

本版的实际投递目的地是本地 SQLite outbox，public/internal 是策略标签，不是互联网地址。不能据此宣称已解决整体 AI 失控，也没有原创性或独立安全认证结论。
